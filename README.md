# AblSchedule

Адаптивное приложение для согласования расписания баскетбольного турнира. Next.js 16, React 19, TypeScript, PostgreSQL. Для автономной локальной разработки поддерживается SQLite из Node.js 24.

## Запуск на Windows

Установите Node.js 24 LTS. Распакуйте архив проекта в отдельную папку и дважды нажмите `start-windows.cmd`. Скрипт установит зависимости, создаст локальную конфигурацию с новым ключом сессии (если её ещё нет), подготовит демоданные и запустит приложение. После сообщения `Ready` откройте http://localhost:3000. Окно запуска оставьте открытым; для остановки нажмите Ctrl+C. При повторном запуске существующие настройки и данные сохраняются. GitHub Desktop для этого способа запуска не требуется.

## Быстрый запуск

Нужен Node.js 24+. В существующем checkout (отдельный worktree не нужен):

```sh
npm ci
cp .env.example .env.local
```

В `.env.local` задайте `SESSION_SECRET` — случайную строку не короче 32 символов. Для локальной демонстрации задайте `DEMO_MODE=true` и, при желании, `DATABASE_PATH=data/demo.sqlite`. Секрет можно создать командой `openssl rand -hex 32`, сохраните его только в локальной конфигурации. Файлы `.env*` и `data/` исключены из Git.

```sh
npm run demo:seed  # только при DEMO_MODE=true; существующую базу не заменяет
npm run dev
```

Демонстрационные кнопки «Капитан A», «Капитан Б», «Организатор» позволяют пройти сценарий без Telegram. Они работают **только** при явном `DEMO_MODE=true`. Не включайте этот режим на публичном рабочем сервере. Названия и пары в начальном наборе — демонстрационные, их нужно заменить в админке. Исходные логотипы не загружались; вместо них отображаются инициалы, в админке можно указать HTTPS URL логотипа.

`npm run build && npm start` — production-сборка. В облачной среде сервер запускается на `0.0.0.0:3000`. В браузере показывается только опубликованное расписание; капитаны и организатор видят также неопубликованные туры. Время всегда МСК (UTC+3).

## Telegram и рабочий запуск

1. Создайте бота в BotFather. В защищённой конфигурации приложения задайте `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` (без @), `TELEGRAM_WEBHOOK_SECRET` (случайная строка), `SESSION_SECRET`.
2. Задайте `APP_URL` — канонический публичный HTTPS-адрес приложения, без завершающего слеша, и `ADMIN_TELEGRAM_IDS` — числовые Telegram ID организаторов через запятую. Установите `DEMO_MODE=false`.
3. Зарегистрируйте webhook официальным методом Telegram Bot API `setWebhook`: `url` = `${APP_URL}/api/telegram/webhook`, `secret_token` = значение `TELEGRAM_WEBHOOK_SECRET`, `allowed_updates` = `["message"]`. Передавайте токен через защищённый инструмент, не вставляйте его в Git, скриншоты, журнал или чат. Для работы webhook сервер должен быть доступен Telegram по HTTPS. Webhook не регистрируется приложением автоматически.
4. Перезапустите приложение. Нажмите «Войти через Telegram», откройте полученную ссылку, нажмите «Запустить» в боте и вернитесь в тот же браузер. Одноразовая ссылка живёт 5 минут; сессия в HttpOnly-cookie — 7 дней. ID отправляется ботом; пользователю без команды он также показан в кабинете.
5. Организатор привязывает Telegram ID к команде в админке. Один ID соответствует одной команде. Проверьте предложения и уведомления двумя реальными аккаунтами до начала турнира.

Для PostgreSQL задайте `DATABASE_URL`, например `postgresql://USER:PASSWORD@HOST:5432/DB` с настоящими значениями только в защищённой конфигурации. База должна быть создана, таблицы приложение создаёт автоматически. Подключение к удалённой базе должно использовать требуемый провайдером TLS; проверка сертификатов не отключается. Данные SQLite автоматически в PostgreSQL не переносятся. Делайте резервные копии рабочей базы.

Данные турнира хранятся одним JSON-агрегатом с блокировкой строки в транзакции (`FOR UPDATE` в PostgreSQL, `BEGIN IMMEDIATE` в SQLite). Для одной площадки на 32 команды это сохраняет согласованность параллельных действий. Для нескольких крупных турниров потребуется разделение на отдельные таблицы и миграции.

В управляемой облачной среде сетевые вызовы Node.js должны использовать штатный прокси: запускайте Node.js 24 с `NODE_USE_ENV_PROXY=1`, сохраняйте предоставленную CA-конфигурацию. Для Telegram требуется доступ к `api.telegram.org`. Вне облачной среды эта переменная обычно не нужна.

## Согласование в расписании

Капитан выбирает несколько подходящих слотов кнопками «Выбрать этот слот» прямо в карточках вкладки «Расписание». Выбранные карточки подсвечиваются. Соперник видит в тех же карточках кнопку «Подтвердить этот слот». Подтверждение одного времени сбрасывает остальные предложения этой пары. В занятой карточке видны уже согласованные пары и предупреждение о возможном конфликте; выбор остаётся доступен. Отдельной вкладки «Мой матч» нет. Пересогласование открывается в блоке своей пары над карточками.

## Управление турами

В админке три раздела: **Выбранный тур**, **Новый тур**, **Команды и капитаны**. Выбранный тур указан в переключателе и заголовке рабочей области. Его сроки, матчи, конфликты, публикация и дополнительные настройки слотов относятся только к нему. Список слотов свёрнут, чтобы не перегружать экран.

В разделе «Новый тур» одна форма создаёт даты, пары и слоты одновременно. По умолчанию — по 8 слотов с 10:00 в субботу и воскресенье. Начало и количество в день можно изменить; предварительный список времени виден сразу. Шаг и длительность — 70 минут; игры должны закончиться до полуночи, общее число слотов — не меньше 16. Создание не меняет предыдущие туры и открывает созданный тур для дальнейшей работы. Введённые данные сохраняются при переключении разделов до создания. Справочник команд общий для всех туров.

Карточки используют локальный шрифт Montserrat с кириллицей (лицензия OFL в `public/fonts/OFL.txt`), фактурный фон и компактную компоновку по предоставленному образцу. Счёт матчей не добавлен.

## Правила и админка

- 32 команды, 16 неповторяющихся пар на тур, одна площадка на Профсоюзной.
- По умолчанию восемь 70-минутных слотов в субботу и воскресенье: 10:00–18:10. Дополнительные слоты не должны пересекаться. Используемый слот удалить нельзя.
- При выборе субботы нового тура окно автоматически заполняется предыдущими понедельником 12:00 и вторником 18:00. Организатор может его изменить, в том числе повторно открыть после дедлайна.
- Каждая команда предлагает несколько слотов. Подтвердить можно только предложение соперника. После подтверждения предложения этой пары очищаются, предложения других пар сохраняются.
- Несколько пар могут подтвердить один слот; все участники видят занятость. Это конфликт, решение за организатором. Он назначает время вручную, затем публикует тур целиком — только когда все игры назначены и конфликты устранены.
- До публикации и внутри окна капитан может открыть пересогласование: прежнее время своей пары освобождается, нужны новые предложение и подтверждение. После публикации изменения делает организатор, без создания конфликта.
- Пары текущего тура редактируются до появления первых предложений. Новый тур можно создать вручную или из `.xlsx` — первая строка `Команда 1` / `Команда 2`, далее 16 строк с точными названиями команд. Шаблон доступен в админке и `public/pairs-template.xlsx`. Импорт сначала заполняет редактируемый список; сохранение проверяет 32 уникальные команды.
- Уведомления в Telegram отправляются при предложении, подтверждении, пересогласовании, назначении и публикации. При конфликте уведомляются затронутые пары и организаторы. Ошибка доставки не откатывает расписание и показывается пользователю. Фоновой очереди повторной доставки и автоматических напоминаний по таймеру в этой версии нет.
- Интерфейс обновляется каждые 15 секунд и после действий. У публичных посетителей скрыты черновики, частные предложения и Telegram ID капитанов.

## Проверки

```sh
npm test                 # 8 тестов правил турнира
npm run typecheck
npm run build
npx playwright install chromium
npm run test:e2e
```

Если Chromium уже установлен: `CHROMIUM_PATH=/usr/bin/chromium npm run test:e2e`. E2E запускает production-сборку на отдельном порту 3100 с новой SQLite-базой и случайным ключом сессии, проходит роли капитанов и организатора, конфликт, публикацию, мобильную ширину, импорт Excel и проверки доступа. Деморежим не доказывает работу реального Telegram: интеграцию нужно проверить с настроенным ботом и HTTPS.

Проверка адаптеров хранения на **тестовой** базе (меняет первый элемент справочника; не запускайте на рабочих данных):

```sh
DATABASE_PATH=data/storage-test.sqlite node --import tsx tests/storage.ts
DATABASE_URL=postgresql://postgres@localhost:5432/abl_test node --import tsx tests/storage.ts
```

Проверяются 12 конкурентных изменений, откат транзакции и сохранение токенов входа. Скриншоты E2E сохраняются в игнорируемой папке `data/`. Секреты и процессы не входят в исходники. Облачный draft и публикация окружения выполняются отдельно от Git и развёртывания приложения.
